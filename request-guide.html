リクエストが届いたら

メールでリクエストが届いてから、作品を公開して「リクエスト対応予定」が「できました」になるまでの手順です。
画面のボタンや項目の名前は こう、管理ツールのタブは こう 書いています。

  1. 1メールを読んで
    作るか決める
  2. 2管理ツールに
    取り込む
  3. 3進み具合を
    決めて公開
  4. 4イラストを
    作る
  5. 5作品を
    登録する
  6. 6公開して
    お知らせ
大事なこと：リクエストは自動ではサイトに載りません。 作ることにしたリクエストを管理ツールで追加して、公開すると「リクエスト対応予定」に出ます。それまで、送ってくれた人の画面には「受け取りました」と表示されています。
追加したリクエストは、内容とニックネームをサイトに載せます（フォームに「サイト掲載OK」のチェックはありません。送る人には、フォームとプライバシーポリシーでその旨を知らせています）。

使うもの

ファイル 何をするもの 開く画面
manager.bat 管理ツール。リクエスト・作品の編集と、公開をします。 http://127.0.0.1:4400/
run.bat 確認用のサイト。保存した内容が、公開前にどう見えるか確かめます（使わなくても進められます）。 http://localhost:4321/…

どちらもダブルクリックするとブラウザが開きます。終わるときは、黒いウィンドウを閉じます。

手順

1

メールを読んで、作るか決める

メール

リクエストは Formspree からメールで届きます。本文はこの形です。

【受付番号】R-7K2M
【ニックネーム】もふ           ← 書いてあるときだけ
【ベースの作品】からっぽシャツの白髪狐っ娘 (144)   ← 作品ページから来たときだけ

【リクエスト内容】
ぶかぶかのパーカーで、ねむそうな顔でぬいぐるみを抱っこ

どんな子？: ネコミミ            ← えらんだもの（あるときだけ）
ポーズ: ピース
【以上】
  • 作るかどうかを、ここで決めます。作ることにしたものを、手順 2 で取り込みます。作らないものは、取り込まなくてかまいません（一覧には載らず、送ってくれた人の画面は「受け取りました」のままです）。
  • メールアドレスが書かれていたら、返信がほしい人です。返信はメールで直接送ります（管理ツールからは送れません）。
  • R-18（成人向け）など、受けられない内容でないかも見ておきます。
  • 取り込んだリクエストは内容をサイトに載せるので、載せて困る内容（個人的なこと、ほかの人の名前など）が書かれていないかも見ておきます。
2

管理ツールに取り込む

管理ツール ＞ リクエスト
  1. メールの本文をコピーします（【受付番号】から【以上】まで。メール全体でも大丈夫です）。
  2. manager.bat を開き、リクエスト の メールから取り込む に貼り付けて、読み取る を押します。
  3. 受付番号・ニックネーム・内容が表示されます。すぐに対応を決めない場合は 保留に保存 を押します。対応すると決めた場合は リクエスト対応予定に追加 を押します。

保留に保存 した内容は、この PC の管理ツール内の「保留中」一覧に保存されます。サイトや公開データには出ません。後から一覧で内容を確認して「対応予定に追加」または削除できます。

追加すると、進み具合は 受付 になり、そのリクエストの編集画面が開きます。

内容をサイトに載せたくないリクエストは、編集画面で 内容をサイトに載せる のチェックを外して保存します。内容とニックネームはこの PC の中だけに保存され、サイトにも GitHub にも出ません（サイトには受付番号と進み具合だけが載り、管理ツールの一覧には「非公開」の印が付きます）。
3

進み具合を決めて、いったん公開する

管理ツール ＞ リクエスト → 公開
  1. 進み具合 を選びます。もう作りはじめているなら 制作中、これから作るなら 受付 のままにします。
  2. ひとこと伝えたいときは 作者の返信 に書きます（「いま作ってます！」など。サイトに表示されます）。
  3. 自分用の覚え書きは 作業メモ に書きます（公開されません）。
  4. 保存する を押します。
  5. 公開 を開いて 公開する を押します。数分後、サイトに反映されます。
ここで一度公開しておくと、送ってくれた人が次に来たとき、自分のリクエストが「受付」や「制作中」になっているのが見えます。これが「また来たくなる」きっかけになります。
公開先は https://mopslipper.github.io/mopslipper-Illustration-site/ です。反映には数分かかります。インターネットにつながっていないと公開できません。
4

イラストを作る

いつもの制作

いつもどおり制作します。背景は基本的に白背景、という案内をリクエストページに出しています。

  • 途中で伝えたいことができたら、作者の返信 を書き換えて、保存 → 公開します。
  • 作るのをやめるときは、進み具合を 見送り にして、保存 → 公開します。
5

できあがった作品を登録する

管理ツール ＞ リクエスト → 作品
  1. リクエスト でそのリクエストを開き、このリクエストから作品を登録 を押します。作品の登録画面に移ります。
  2. 点線の枠に、画像をドラッグ＆ドロップします（クリックして選んでも大丈夫です）。サムネイルは自動で作られます。
  3. タイトル を入力し、タグ を付けます。タグは、下に並ぶ候補を押すだけでも追加できます。
  4. 説明 を書きます。AI で説明文を生成 も使えます（API キーの設定が必要です）。
  5. ちょっとセクシーな作品は R-15 にチェックを入れます。
  6. 登録する を押します。
保存すると、リクエストの進み具合が自動で できました になり、サイトで作品とリクエストが相互にリンクされます。作品ページには「リクエストから生まれた作品です」と表示されます。

複数枚の作品は、追加画像・サムネイル・X カード を開いて追加画像を登録します。

6

公開して、お知らせする

管理ツール ＞ 公開 → X
  1. 公開 を開いて 公開する を押します。公開の前に、データに問題がないか自動で確かめます。
  2. 数分後、サイトに作品が並び、「リクエスト対応予定」が「できました」になります。
  3. X に投稿します。リクエスト文を画像にして添えたいときは、リクエスト でそのリクエストを開き、X 投稿用の画像を作る → PNG を保存 を使います。
  4. トップページでも知らせたいときは、サイト の ひとこと に書いて、保存 → 公開します。
内容をサイトに載せる のチェックを外したリクエストの文を X に載せるのは、サイトに載せるのと同じことです。画像にして投稿してよいか、確かめてから使ってください。

進み具合の使い分け

進み具合 いつ使う 送ってくれた人に見えるもの
受け取りました （選べません）まだ管理ツールで追加・公開していない間の表示です。 自分の画面の「あなたのリクエスト」にだけ出ます。一覧には出ません。
受付 取り込んだ直後。作る予定で、まだ作りはじめていないとき。 「リクエスト対応予定」の一覧と、自分の画面の「あなたのリクエスト」の両方に出ます。「できました」には作品へのリンクが付きます。
制作中 作りはじめたとき。
できました 作品を登録したとき（手順 5 で自動で変わります）。
見送り 一度は載せたけれど、作るのをやめたとき。

公開されるもの・されないもの

項目 サイトに出る？ 補足
受付番号・日付・進み具合 出る 内容をサイトに載せる のチェックを外したリクエストでも出ます。
作者の返信・できあがった作品 出る 書いたとき・紐付けたときだけ。
リクエスト内容・ニックネーム 出る / 出ない ふだんは出ます。内容をサイトに載せる のチェックを外したときだけ出ず、「（内容は非公開のリクエストです）」と表示されます。
作業メモ 出ない この PC の中だけに保存されます。
メールアドレス 出ない 管理ツールには取り込みません。メールにだけ残ります。

内容をサイトに載せる は、取り込み・手入力のどちらでも最初からチェックが入っています。「サイト掲載OK」のチェックがあった頃のメールで【サイト掲載】掲載しない と書かれているものだけ、取り込み時にチェックが外れます。

こんなときは

受けられない内容だった（R-18 など）

取り込まずに、そのままにします。一覧には載らず、送ってくれた人の画面は「受け取りました」のままになります。

受けられないことを伝えたいときは、取り込んだうえで 内容をサイトに載せる のチェックを外し、進み具合を 見送り にして、保存 → 公開します。理由は 作者の返信 に書けます。

X の DM など、メール以外でリクエストをもらった

リクエスト の 手入力で追加（X の DM など） を押して、内容を入力します。受付番号は、空欄のままなら自動で付きます。

フォームから送られたものと違い、DM の相手は内容がサイトに載ることを知りません。載せてよいか聞けていないときは、内容をサイトに載せる のチェックを外して追加します。

「読み取る」を押しても読み取れない

貼り付けた文章に【受付番号】R-XXXX の行が入っているか確かめてください。入っているのに読み取れないときは、手入力で追加 を使い、受付番号 にメールの番号を入力すれば、同じように扱えます（番号が同じなら、送ってくれた人の画面にも進み具合が出ます）。

「この受付番号はすでに登録されています」と出た

同じメールを取り込み済みです。開く を押すと、そのリクエストの編集画面が開きます。

掲載を取り下げてほしいと連絡が来た

そのリクエストを開き、内容をサイトに載せる のチェックを外して、保存 → 公開します。内容とニックネームがサイトから消え、受付番号と進み具合だけが残ります。

番号ごと消したいときは 削除 を押して、公開します。

一度公開した内容は、サイトからは消えますが、GitHub の過去の履歴には残ります。

ひとつの作品が、複数のリクエストに応えている

作品 でその作品を開き、元になったリクエスト の一覧から、もうひとつのリクエストを選んで保存します。選んだリクエストも「できました」になります。

過去にリクエストから作った作品も、一覧に載せたい

手入力で追加 でリクエストを作り、できあがった作品 でその作品を選びます。進み具合は自動で「できました」になります。

公開する前に、どう見えるか確かめたい

run.bat を開いておくと、管理ツールの右上に サイトを確認 ↗ が出ます。保存した内容は、確認用のサイトにすぐ反映されます。

「公開する」を押したら、問題があると表示された

どのファイルの何が問題かが一覧で出ます（画像が見つからない、など）。直してから、もう一度 公開する を押します。問題がある間は公開されないので、サイトが壊れることはありません。

「公開する」を押したのに、サイトが変わらない

反映には数分かかります。ブラウザを再読み込みしても変わらないときは、管理ツールの 公開 に出る結果（実行した内容）を確認してください。

「公開しました」と出ているのに変わらない場合は、GitHub 側の処理（テスト・ビルド）が失敗している可能性があります。GitHub のリポジトリの Actions タブで結果を確認できます。失敗している間、サイトは前の状態のまま表示されます。

まちがえて保存・削除してしまった

data/private/backup/ に、保存する直前のデータが残っています（各ファイル直近 20 回分。requests.20261114-190512-123.json のように日時が付いています）。戻したい時点のファイルを data/ にコピーし、名前を requests.json のように元の名前に直すと、元に戻せます。

PC を替える

data/private/ フォルダは、この PC にしかありません（サイトに載せていないリクエストの内容と、作業メモが入っています）。フォルダごと新しい PC にコピーしてください。
