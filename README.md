# mopslipper - Portfolio of Illustrations (v2)

個人イラストのポートフォリオサイト。「気軽にリクエストできて、その結果を見に戻ってこられる小さなアトリエ」を目指した v2 です。

- 公開 URL: https://mopslipper.github.io/mopslipper-Illustration-site/
- リポジトリ: `mopslipper/mopslipper-Illustration-site`（main ブランチに push すると自動で公開されます）
- 掲載は R-15 まで（`nsfw: true` の作品はビルドに含めません）
- 静的サイトのみ（GitHub Pages）。外部サービスは Formspree（フォーム）と Abacus（閲覧数・いいね）

**このフォルダが正本です。** 以前の作業フォルダ（`6-mopslippers-illustration_site`）は v1 の控えで、もう使いません（そこから push すると、このフォルダの内容と食い違います）。

## ふだんの使い方

| やりたいこと | 方法 |
| --- | --- |
| 作品・リクエスト・サイトの文章を編集する、公開する | `manager.bat` をダブルクリック（管理ツール） |
| 公開前にサイトの見た目を確かめる | `run.bat` をダブルクリック（確認用のサイト） |

どちらもブラウザが開きます。終了するときは、起動したウィンドウを閉じます。

リクエストが届いてから公開するまでの手順は、[request-guide.html](./request-guide.html)（ダブルクリックでブラウザで開けます）にまとめています。

## 構成

- `site/` … Astro 製の静的サイト本体
- `data/` … サイトのデータ（下の表）
- `static/img/` … 画像・動画の原本（管理ツールと Astro が共有）
- `tools/manager/` … 管理ツール（ブラウザで操作）。`manager.bat` で起動
- `tools/` … 限定共有コンテンツの暗号化ツール、閲覧数の取得スクリプト

| ファイル | 内容 | 更新方法 |
| --- | --- | --- |
| `data/works.json` | 作品 | 管理ツール「作品」 |
| `data/requests.json` | リクエストのゆくえ（公開される分） | 管理ツール「リクエスト」 |
| `data/notes.json` | トップの「ひとこと」 | 管理ツール「サイト」 |
| `data/request_options.json` | リクエストフォームの選択肢 | 管理ツール「サイト」 |
| `data/commission.json` | 有償依頼（受付状態・メニュー） | 受付状態は管理ツール「サイト」、メニューは手編集 |
| `data/config.json` | サイト設定・公開先 | 手編集 |
| `data/counts.json` | 閲覧数・いいねの日次スナップショット | GitHub Actions が自動更新 |
| `data/private/` | この PC だけのデータ（下記） | 管理ツールが自動で管理。**git には入りません** |

## 管理ツール

`manager.bat` をダブルクリックすると、ブラウザで管理画面（`http://127.0.0.1:4400/`）が開きます。Node.js（22.18 以上）だけで動きます。

保存した内容は、**「公開」するまでサイトには出ません**（確認用のサイト `run.bat` にはすぐ反映されます）。

### リクエスト

1. 届いたメールの本文（【受付番号】から【以上】まで。メール全体でも可）をコピーして、「メールから取り込む」に貼り付け →「読み取る」
2. 読み取った内容を確かめて「リクエストのゆくえに追加」
3. 進み具合（受付 → 制作中 → できました／見送り）、作者の返信、作業メモを編集して保存

- **リクエストは自動では載りません。** 作者が追加したものだけが「リクエストのゆくえ」に出ます（静的サイトのため。いたずらや不適切な内容がそのまま公開されるのを防ぐ意味もあります）
- X の DM など、メール以外で受けたものは「手入力で追加」。受付番号は自動で付きます
- 「このリクエストから作品を登録」を押すと作品の登録画面に移り、保存するとリクエストが「できました」になって、サイトで作品と相互にリンクされます
- 「X 投稿用の画像を作る」で、リクエスト文をマシュマロ風の画像（1200×630 の PNG）にできます

#### 公開される内容・されない内容

| | 保存先 | サイトに出る？ |
| --- | --- | --- |
| 受付番号・日付・進み具合・作者の返信・できあがった作品 | `data/requests.json` | 出る |
| 内容・ニックネーム（「内容をサイトに載せる」にチェックがあるとき） | `data/requests.json` | 出る |
| 内容・ニックネーム（チェックが無いとき） | `data/private/requests_private.json` | **出ない** |
| 作業メモ | `data/private/requests_private.json` | **出ない** |

- メールが【サイト掲載】OK のときだけ、取り込み時に「内容をサイトに載せる」にチェックが入ります。あとからチェックを入れるときは、送り主の同意があるかを確認する画面が出ます
- チェックを外して保存すると、内容は `data/requests.json` から消えます。ただし、すでに公開（push）した分は GitHub の履歴に残ります
- `data/private/` は `.gitignore` 済みで、この PC にしかありません。**PC を替えるときは、このフォルダごとコピーしてください**
- `data/private/backup/` には、保存する直前のデータファイルが残ります（各ファイル直近 20 回分）。操作を誤ったときはここから戻せます

### 作品

- 画像・動画を枠にドラッグ＆ドロップ（またはクリックして選択）すると、`static/img/works/` に `{ID}.{拡張子}` の名前で保存され、JPG のサムネイルが自動で作られます。動画の作品は、サムネイル画像を別に登録します
- タグは入力するか、下に並ぶ候補（よく使うタグ）から追加します
- 「AI で説明文を生成」は、OpenAI の API キーが必要です。旧フォルダの `api_keys.json` / `ai_config.json` をこのフォルダ直下にコピーしてください（秘密情報のため `.gitignore` 済み。画面の「設定ファイルのひな形を作る」でも作れます）
- 「非表示」にした作品は、ギャラリーにも作品ページにも出ません
- 削除しても、画像ファイルは `static/img/works/` に残ります
- 外部リンク（Pixiv / X など）とリクエストタグは、この画面では編集しません。既存の作品に付いているものはそのまま残り、サイトにも表示され続けます

### サイト

- **ひとこと**: トップページに、新しいものから3件が表示されます。リンクは任意で、`/gallery.html?tag=巫女` のようなサイト内パスか URL を書けます
- **リクエストフォームの選択肢**: リクエストページの「えらぶだけでもOK」に並ぶ選択肢です。いちばん上のグループは「お題ガチャ」で必ず1つ選ばれます。作品ページの「この子の別バージョンをリクエスト」のボタンもここで編集します
- **有償依頼の受付**: 受け付ける／受け付けないと、表示する文言を切り替えます。料金メニューなどは `data/commission.json` を直接編集します

### 公開

- まだ公開していない変更が、種類ごとに一覧で出ます
- 「公開する」を押すと、**公開前チェック**（データの書式、ID・slug の重複、画像ファイルの有無、リクエストと作品の対応）→ 記録（commit）→ リモートの変更の取り込み → 送信（push）の順に行います。チェックで問題が見つかったときは公開しません
- 数分後に、公開 URL へ反映されます。途中でテストやビルドが失敗した場合、サイトは前の状態のまま表示され続けます（結果は GitHub の Actions タブで確認できます）
- ボタンが「変更を記録する」になっているときは、公開先（リモート）が設定されていません。その間は記録（commit）までで止まります

### 安全のための仕組み

- 管理ツールは、この PC からしか開けません（`127.0.0.1` だけで待ち受けます）
- ほかのサイトを開いているブラウザからは、読み取りも書き込みもできません
- OpenAI の API キーは、ブラウザには渡しません

## 開発

```
cd site
npm install
npm run dev      # 確認用のサイト（ルートの run.bat でも起動可）
npm test         # 契約テスト (vitest)。管理ツールのテストも含みます
npm run build    # 本番ビルド
npm run preview  # ビルド結果の確認
```

`data/*.json` を手で書き間違えても、`npm test` と `npm run build` が失敗して教えてくれます（管理ツールは、保存のたびに同じ決まりで確かめています）。

管理ツールは `tools/manager/` にあります。`server.mjs`（起動）、`lib/`（データの読み書き・検証・画像処理・git。サイトと同じスキーマ `site/src/lib/schema.ts` を使います）、`public/`（画面。ビルド不要）。`node tools/manager/server.mjs --root <フォルダ>` で、別のフォルダのデータを相手に動かせます。

`requirements.txt` は `tools/encrypt_share.py`（Cliant Share の暗号化）用です。

## ページ

| URL | 内容 |
| --- | --- |
| `/` | 新着、ひとことリクエスト欄、リクエストのゆくえ、ひとこと |

| `/works/{slug}.html` | 作品。似た雰囲気の作品、別バージョンのリクエスト |

作品・ギャラリーなどの URL は旧サイトと同じです。旧サイトの `contact.html?from=work&slug=...` リンクはリクエストページへ自動で引き継ぎます。

## リクエストの届き方

`/request.html` から送られたリクエストは、Formspree 経由でメールで届きます。本文はこの形です（管理ツールがそのまま読み取れます）。

```
【受付番号】R-7K2M
【サイト掲載】OK            ← 「掲載しない」のときは内容を公開しない
【ニックネーム】もふ         ← 書いてあるときだけ
【ベースの作品】からっぽシャツの白髪狐っ娘 (144)   ← 作品ページから来たときだけ

【リクエスト内容】
ぶかぶかのパーカーで、ねむそうな顔でぬいぐるみを抱っこ   ← 自由に書いた文章

どんな子？: ネコミミ                                    ← えらんだもの（あるときだけ）
ポーズ: ピース
【以上】
```

送った人のブラウザには受付番号が保存され、次に来たときに「あなたのリクエスト」として進み具合が表示されます。管理ツールで追加して公開するまでは「受け取りました」と表示されます。

`data/requests.json` の1件は次の形です（管理ツールが書き出します）。

| 項目 | 必須 | 内容 |
| --- | --- | --- |
| `id` | ○ | 受付番号（`R-` + 英大文字・数字3〜8文字） |
| `date` | ○ | 受け取った日（`YYYY-MM-DD`） |
| `status` | ○ | `received`（受付）/ `making`（制作中）/ `done`（できました）/ `declined`（見送り） |
| `public` | ○ | 内容をサイトに載せるか。`false` のリクエストには `text` と `nickname` を書けません（テストとビルドが失敗します） |
| `text` |  | リクエスト内容（`public: true` のときは必須） |
| `nickname` |  | ニックネーム |
| `work_slug` |  | できあがった作品の slug。作品ページに「リクエストから生まれた作品です」と表示され、相互にリンクされます |
| `reply` |  | 作者の返信 |

## R-15 の扱い

- `sensitive: true`（R-15）の作品は、年齢確認の回答に関係なく通常どおり表示します。カードと作品ページに小さな「R-15」の目印が付き、ギャラリーで「R-15 作品のみ」に絞り込めます
- 初回に出る年齢確認は「R-15 の作品があります」という案内です。回答はブラウザに記録するだけで、表示内容は変えません
- `nsfw: true`（R-18）の作品は掲載しません。旧データとの互換のため項目は残していますが、ビルド時に除外されます。管理ツールには R-18 の設定はありません

## 公開先の切り替え

公開 URL は `data/config.json` の2項目だけで決まります。

```json
"site_url": "https://mopslipper.github.io",
"base_path": "/mopslipper-Illustration-site"
```

いまは v1 と同じ URL のまま公開しています。別のリポジトリで公開する場合は、`base_path` を `"/新しいリポジトリ名"` に変更します（独自ドメインなどルート直下なら `""`）。

一時的に変えたいだけなら、環境変数 `SITE_URL` / `BASE_PATH` でも上書きできます。

## v1 に戻すには

v2 への切り替えは 1 つのコミット（`Renew site as v2: ...`）にまとめてあります。そのコミットを取り消して push すると、数分で v1 のサイトに戻ります。

```
git revert <リニューアルのコミット>   # git log で確認できます
git push
```

タグ `v1-final` が、v1 の最後の状態を指しています。閲覧数・いいねと Formspree は、切り替えの影響を受けません。

## デプロイ

main ブランチへの push（管理ツールの「公開する」）で GitHub Actions（`.github/workflows/deploy.yml`）がテスト → ビルド → GitHub Pages 公開を行います。リポジトリの Settings → Pages で Source を「GitHub Actions」にしてください。

## 閲覧数・いいね機能

カウントは無料カウンター API([Abacus](https://abacus.jasoncameron.dev), namespace `mopslipper-illustration-site`, キー `views-{id}` / `likes-{id}`)に保存されます。

| 場所 | 表示方法 | 更新タイミング |
| --- | --- | --- |
| 作品詳細ページ | `counter.ts` が API を直接呼ぶ | リアルタイム(ページを開くたびに閲覧数 +1) |
| ギャラリーのカード | ビルド時に `data/counts.json` から静的に埋め込み | 1日1回(最大約1日遅れ) |

ギャラリーを静的表示にしているのは、1ページに数十作品が並ぶためページ表示ごとに全作品分の API を呼ぶと Abacus のレート制限(30リクエスト/10秒/IP)に達するためです。

日次更新: 毎日 JST 3:00 に `.github/workflows/update-counts.yml` が `tools/fetch_counts.mjs` を実行し、`data/counts.json` に変化があれば自動 commit → 再デプロイします（手動実行: Actions タブ → update-counts → Run workflow）。管理ツールの「公開する」は、送る前にこの自動更新を取り込みます。

- いいねは1作品につき1回まで(取消不可、`localStorage` の `liked-{id}` で判定)
- Abacus のキーは最終アクセスから6ヶ月で失効するが、日次取得がアクセスを兼ねるため実質失効しない
